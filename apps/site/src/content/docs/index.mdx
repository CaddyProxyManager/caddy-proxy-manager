Caddy is a web server that gets TLS right by default. Caddy Proxy Manager is a UI in front of it, so
the things Caddy can do - reverse proxying, certificates, a WAF, layer-4 streams - become things you
configure and watch rather than things you write into a config file and hope about.

## What it does

<CardGrid>
  <Card title="Reverse proxy" icon="random">
    Multiple upstreams, twelve load-balancing policies, health checks, upstream timeouts, custom
    headers, location rules, redirects, rewrites, asset caching, compression, rate limiting,
    maintenance mode, Force HTTPS and HSTS, upstream DNS pinning, live upstream health, tags, and
    bulk actions across hosts.
  </Card>
  <Card title="L4 TCP/UDP proxy" icon="puzzle">
    Layer 4 stream proxying. Port ranges, TLS SNI matching, PROXY protocol, health checks, geo
    blocking and access-list IP rules below HTTP.
  </Card>
  <Card title="Automatic HTTPS" icon="approve-check">
    ACME through Let's Encrypt or any directory you point it at, DNS-01 across twenty-two providers
    with challenge delegation, certificates read from files on an agent's host, plus a built-in CA
    for mutual TLS.
  </Card>
  <Card title="WAF" icon="warning">
    Coraza with the OWASP Core Rule Set. Per-host control, rule suppression, and a searchable event
    log that shows the rule that fired beside each event.
  </Card>
  <Card title="Traffic analytics" icon="bars">
    Live request charts, protocol breakdown, a country map, top user agents and blocked requests,
    backed by ClickHouse - plus a live view of the raw access, WAF and Caddy logs.
  </Card>
  <Card title="Accounts, audited" icon="list-format">
    Sign in with a password, a passkey, SSO or LDAP/Active Directory. Every configuration change is
    recorded with the account that made it, and searchable. The whole configuration backs up to one
    encrypted file.
  </Card>
</CardGrid>
